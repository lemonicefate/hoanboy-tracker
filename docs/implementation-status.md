## 架構

- Python 3.11+、Flask、Waitress、SQLite；Windows 本機 `127.0.0.1`，一個操作帳號、一個服務程序。
- `device.py`：實際觀察的唯讀協定；先選庫再讀表，重選庫與重讀比較 schema。可檢出可觀察的結構干擾；無法保證相同 schema 的外部選庫干擾不存在。
- `service.py`：共用同步工作、來源鍵與內容去重、版本、人工歸檔事件、歷史／趨勢及報告保存。
- `mapping.py`：明列候選欄名、單位與特殊拼字。缺值／解析失敗不轉零；沒有驗證證據的欄位不成為正式趨勢。
- `reports.py`、`templates/report.html`：十區核對稿，將病人表頭、當次輸入、截止歷史、映射與模板、HTML/CSS 一起保存。所有包含被重新歸檔量測的報告均失效。
- `backup.py`：SQLite 一致性快照、校驗碼、30 使用日保留、隔離還原及筆數／關聯驗證。CLI 啟用還原持有 OS 程序鎖。
- `app.py`：本機 HTTP API；靜態瀏覽器介面使用同一 API。沒有公網服務、遠端同步排程或自動歸檔。

## 需求逐項對照

| User story | 狀態與證據 |
|---|---|
| 1 本機登入 | API 與 browser 測試；雜湊密碼、HttpOnly / SameSite cookie、Origin / Host / CSRF 檢查、登入節流 |
| 2–7 手動／首次同步、摘要、時間、重試、離線 | API 測試首讀／重讀／變更／失敗／重疊；2026-09-27 實際 adapter 讀得 152 欄 15 筆，本機私有驗證庫成功同步 15 筆並備份 |
| 8–9 待歸檔與摘要 | API + browser；來源識別、原始時間、體重／BMI／體脂率與驗證狀態；清單分頁 |
| 10–14 病人建立、病歷號唯一、搜尋、候選、共用手機 | API + browser；前導零保留，手機不唯一、不自動合併；可修改 |
| 15–18 歸檔、解除／重新歸檔、事件、忽略／恢復 | API + browser；單筆單一歸屬，記錄操作員、前後身分、動作及時間；無永久刪除 API |
| 19–22 最新摘要、歷史、明細、同日重測 | API；有效時間排序、保留各筆；原始值、schema 與儲存格保留；時間缺漏不被當成最新 |
| 23–26 曲線、差值、缺值 | API；虛構已核對欄位可畫曲線，保留缺點，不跨缺值假連線。真機欄位仍未核對，不宣稱正式曲線已有驗收資料 |
| 27–28 完整報告及接近原廠版面 | **部分**：十區兩欄核對稿與 A4 單頁測試；原廠長條、節段人形判定、九宮格定位及評估勾選尚缺語義／規則，正式報告未完成 |
| 29 報告歷史 | 保存截止當次的歸檔歷史與 ID，頁面呈現最近五筆來源摘要。原廠多筆繪法仍待驗收，未聲稱還原其圖形規則 |
| 30–31 離線與版本固定 | API + browser：擋外部請求、設備離線仍可重印已存 HTML；後續病人修改／新增量測不改寫舊版；歸檔修正會失效 |
| 32–33 自動／手動備份、還原 | API + CLI + browser；來源、病人、關聯、事件與報告還原；損毀拒絕、失敗可見、保留 30 份、執行中的服務禁止覆寫 |
| 34 效能 | 在本機以 1,000 虛構病人、20,000 虛構量測測試，暖機後搜尋與病人頁 API 均低於 2 秒；測試輸出 `test-results/performance.json` |
| 35 擴充邊界 | 設備 reader 可注入、共用同步工作、所有 SQLite 存取在後端；首版不開多機及定時同步 |

## 已執行的證據

- `tests/test_api.py`：資料流程、登入防護、schema 驗證、錯誤與缺值、來源版本、修正稽核、版本化報告、備份及保留。
- `tests/test_browser.py`：完整關鍵操作路徑，阻擋非本機請求、模擬設備離線；含完整候選數值及五筆歷史的十區報告輸出一頁 A4 PDF；手機寬度頁面可操作。
- `tests/test_cli.py`：Waitress 真程序啟動；執行中拒絕還原，停止後啟用備份，透過 API 核對回復資料。
- `tests/test_performance.py`：大資料 fixture 建置不計時，僅以公開 API 量測查詢；斷言最慢樣本低於 2 秒。
- `uv run mypy`、`node --check hoanboy/static/app.js`：型別與 JavaScript 語法。
- 本機唯讀實機 probe 與 API 同步成功；未輸出病人值，實機資料只在 `private/validation/`。

PDF 自動檢查不等於實體印表機可讀性驗收。性能測試為此台電腦與本機 API，不代表其他診所電腦。

## 仍需完成，不能由測試替代

1. 同一筆來源與完整原廠報告核對所有數值、單位、精度、性別與 Level／體型代碼，取得節段正常／偏高判定來源。核對後才可實作正式圖表／判定及啟用已驗證欄位。
2. 原廠長條比例、多筆歷史繪法、清晰標誌／必要小字素材；完成十區正式版與實際 A4 列印驗收。
3. 設備重測、重啟後讀取與來源鍵持續性、設備時間及時區校準；目前只確認當下唯讀成功，未替使用者重啟設備。
4. 正式使用前指定主機可讀設備除錯介面、Windows 私有目錄存取限制及另一裝置備份設定。需廠商確認正式介面與限制方法。
